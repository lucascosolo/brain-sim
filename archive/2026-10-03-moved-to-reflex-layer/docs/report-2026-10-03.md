## What works (run in this session)

- `python3 -m pytest -q tests/test_executive` → 13 passed (brain-sim).
  `python3 -m pytest -q` in reflex-layer → 15 passed. Both lints are clean apart from the nine
  known plant-test findings, which the brain-sim safety test pins by file.
- The loop, end to end, on tiny generated repositories. Each item is a test:
  - an already passing suite is verified with one sandboxed test run and no other action;
  - a typo (`NameError`) and a missing import are fixed by skills, with no model call;
  - a logic bug reaches an impasse (all three cheaper operators report why they do not
    apply), is escalated once, fixed, and verified;
  - a model answer that fixes the target but breaks another test is detected as a
    regression (prediction error 1.0), rolled back, and the rollback itself verified; the
    second answer, which sees the rejected attempt, succeeds;
  - a model answer that edits a test file is refused by the workspace, and so is a
    schema-violating answer; nothing is applied;
  - with no deliberator, an impasse abandons the subgoal and blocks the goal with the reason,
    with no edits left behind;
  - "no tests collected" blocks instead of reporting success;
  - a second, byte-identical repository is fixed from memory with zero model calls;
  - an interrupted run resumes from `state.json`, including a pending prediction;
  - identical inputs give identical decision traces.
- The sandboxed test runner refuses `os.remove`, `shutil.rmtree`, `Path.unlink`, writes outside
  its run directory (including the repository itself) and `subprocess`. Ordinary temp-file
  cleanup inside its run directory becomes a quarantine move. The audit-hook backstop caught
  a path the function replacement missed (`tempfile`'s private `rmtree` reference), which is
  now covered as well.

## What is mocked or incomplete

- **Every model answer so far is scripted.** `ClaudeCLIDeliberator` is written but has not run
  live: that spends money, and your workflow needs an explicit yes. Token, cost and
  false-confidence numbers from a real model do not exist yet.
- No comparison against a plain Claude CLI workflow yet.
- Only Python, pytest, and one goal kind (make the tests pass). The data model allows several
  goals, but selection uses the first.
- Cognitive compilation is not implemented beyond exact memoization. No skill is generated
  from episodes, and there is no candidate-skill sandbox or promotion pipeline.
- Tiers 3 (evidence gathering as its own operator) and 4 (small or local model) are empty
  slots. Evidence gathering currently happens inside deliberation: it resolves the functions a
  failing test calls, so the model sees the code under test.
- The sandbox is a Python audit hook, not an OS boundary, and it refuses every subprocess.

## Where a model is currently required

Exactly one place: `DeliberatePatch`, when a failing test matches no memory episode and no
skill. In practice that means every failure that is not a `NameError` for a near-typo or for
a uniquely defined name. Everything else is deterministic: observing, deciding, applying,
predicting, judging, rolling back, verifying and remembering.

  existed. The lint shows no deletion primitive in it, and nothing in the checkout changed,
  but it was unconfined code execution.
- Adjacent, not fixed: pytest's own `tmp_path` retention removes old
  `/tmp/pytest-of-$USER/pytest-N` directories, so every repository whose tests use `tmp_path`
  (both of these, and the suite convention) runs a deletion when developers run their tests.
  The executive's sandboxed runner avoids it with `--basetemp` in its run dir.
