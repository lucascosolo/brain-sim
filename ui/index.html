In plain words: when a memory-area cell is very active, it turns up the connections from the cells that were just talking to it and turns down its quieter ones by the same total amount, so it ends up listening more to what was happening at that moment. Only one of this and encode-mode can be on at a time; the simulator refuses the second.

A labelled proxy (SPEC 8.16), not biology. In a wake sweep any hippocampal excitatory cell that fired at least 5 times redistributes weight among its cortical inputs toward the inputs that were active in that sweep, keeping the cell's summed input weight the same. Nobody tells the engine which cells. Scaling, the pair rule and the prunes are untouched. Every number shown is the engine's own value from the frame.

How evidence reconciles

What is allowed to change a command's state, and in what order.

  1. A result sets the command's acceptance or rejection. Nothing else can.
  2. stim_events set start and end when they are observed. Absence from stim_active sets nothing.
  3. A gap (sequence jump or tick discontinuity) marks every command that was accepted and not yet ended as "unknown since t = <last observed tick>", and the client requests stimlog.
  4. A stimlog entry with a matching stim_id fills whatever is unknown; the row then says "recovered from stimlog".
  5. If stimlog does not contain the stim_id — history expired, more than — newer stimuli, or a different run — the row reads "history expired; end never observed" and the timeline bar keeps its open "?" edge while it is in the window. Nothing is filled in.
  6. On reconnect within the same run, layout, config, status and stimlog are re-requested; the unobserved span is a gap and rules 3 to 5 apply.
  7. A result that arrives after the unconfirmed timeout replaces "unconfirmed". Nothing is ever resent automatically.

Rules

The equations the engine runs. Text, not a claim about outcomes.

This list is a description written by hand. The simulator does not report it. The Config (simulator facts) panel above is the checkable source for every key named here that the simulator sends; the rest are named so they can be checked against brainsim/params.py and brainsim/engine.py.

  1. Membrane. Leaky integrate-and-fire with an adaptive threshold: the threshold rises after each spike and relaxes back, so a cell that has just fired needs more drive to fire again.
    keys · dt_ms (config reply) · TAU_M_MS, V_REST_MV, V_RESET_MV, THETA_0_MV, TAU_THETA_MS, D_THETA_MV, T_REF_MS (params.py, not reported)
  2. Pair STDP, potentiation — at a post-synaptic spike:
    w += g · a₊ · x_pre · (w_max − w)
    keys · g_wake, g_sleep (config reply; the live value is frame g) · per-region a_plus, w_max (params.py REGIONS, not reported)
  3. Pair STDP, depression — at delivery:
    w ← max(w · (1 − g · a₋ · y_post), 0)
    keys · g_wake, g_sleep (config reply) · per-region a_minus (params.py REGIONS, not reported)
  4. Traces. x_pre and y_post gain +1 per spike and decay by exp(−1/20) per ms.
    keys · dt_ms (config reply) · TAU_TRACE_MS (params.py, not reported)
  5. Synaptic scaling. Once per sweep, wake only, on excitatory synapses whose presynaptic cell fired in that sweep:
    factor = 1 + clip(0.1 · (r_target − rate) / r_target, ±0.1)
    keys · sweep_ticks, rate_ema_alpha (config reply) · ETA_SCALING, SCALING_CLIP and per-region r_target_exc, r_target_inh (params.py, not reported)
  6. Structural change under a rate setpoint. Once per sweep, the simulator compares each cell's recent firing rate with the target rate for its region and uses the signed error to decide, cell by cell, how many incoming connections to create and how many to destroy. A cell firing below its target grows excitatory inputs; a cell firing above its target loses them, weakest first. Inhibitory inputs are grown or pruned toward a fixed ratio of the excitatory count. Separately, an excitatory connection whose weight has fallen below a fraction of its maximum is destroyed on that sweep. The rate of all of this is scaled by g_struct (shown in the header), which starts high and decays as the run ages.
    keys · sweep_ticks (config reply) · frame g_struct, born_count, died_count, born_per_s, died_per_s, n_syn_alive · STRUCT_BASE, STRUCT_AGE_TAU_S, W_PRUNE_FRAC, W_GROW_FRAC, EI_MOTIF, GROW_BETA, PROJECTIONS and per-region r_target_exc, r_target_inh (params.py, not reported)
  7. Anti-windup. Also once per sweep, the simulator checks whether a group's mean rate error has stopped improving; if it has, it suspends the rate-driven creating and pruning of excitatory inputs for that group until the error changes sign (inhibitory inputs toward the E/I ratio are still created), and reports that as growth_halted. It also stops creating connections everywhere once the connection store is nearly full, reported as store_clamped.
    keys · frame growth_halted, store_clamped · WINDUP_WINDOW_SWEEPS, WINDUP_MIN_PROGRESS, WINDUP_NOISE_SIGMAS, WINDUP_CAP_FRAC, S_MAX (params.py, not reported)
