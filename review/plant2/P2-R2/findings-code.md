## Initial findings

1. **P1 — Resource interruption does not retain the in-flight available state.** The initial driver saves completed learned/index/content stages, but a hard-deadline interruption only emits the stage name, learned-item count and previously completed loads. A partially advanced learning state, or partial evaluation/replay state, is not checkpointed even though the frozen contract explicitly requires checkpointing an in-flight stage. Preserve available state with an explicit incomplete-stage marker. An interrupted `learn_one` may have appended an item before A/E/write completion, so record started-item and completed-write counts separately and never describe that state as a completed learned load. Reserve serialization time inside the existing allocation: computational stopping around minute 19 with an absolute minute-20 deadline is suitable; disabling the hard alarm and serializing afterward must not create a grace period.

2. **P2 — Partial evidence lacks the required per-readout inventory.** The initial final record lists whole missing loads and paired loads only. If index and inherited content complete but assigned-A replay is interrupted, the completed files remain, but the final inventory does not identify precisely which mandatory readout is absent. Derive stage completion from the actual retained checkpoint events and enumerate missing learned/index/inherited-content/assigned-A-content/paired evidence for each arm and load, plus missing seeds in the cross-seed summary.

Both findings were sent promptly to the implementer and parent. The parent requested the early computation-stop/absolute-deadline approach. Closure below will record the implemented fix and final narrow test result.
